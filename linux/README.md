# NextVPN для Linux

Версия NextVPN на GTK 4 и libadwaita для Fedora, CachyOS / Arch, NixOS, Ubuntu и
других дистрибутивов. Тот же движок, те же серверы и те же возможности, что у
версии для Windows. Работает в любом окружении — GNOME, KDE Plasma, Hyprland
(caelestia и другие оболочки на quickshell), Sway, niri, i3: в режиме VPN через
туннель идут все программы.

## Те же серверы, что и у Windows-версии

Linux-версия запускает тот же движок **psiphon-tunnel-core** и читает те же файлы
из [`engine/`](../engine): `base.config` (идентификатор спонсора, канал
распространения, ключи подписи) и встроенный список серверов `server_list.dat`.
Эти поля передаются движку байт-в-байт, ничего не меняется. Серверная сеть та же.

Серверы Psiphon различают клиентов по началу поля `ClientPlatform`: всё, что
начинается с `Windows`, получает настройки для Windows, всё остальное — «Other».
Поэтому по умолчанию Linux-версия представляется серверам так же, как
Windows-версия (`Windows_<версия>_NextVPN`), и получает от них те же тактики,
протоколы и стартовые страницы. В **Настройки → Подключение → «Представляться
серверам как»** можно выбрать честное `Linux`.

| Ubuntu 24.04+, Debian 13+, Mint 22+ | [nextvpn_1.1.0-1_amd64.deb](https://github.com/Just-ElC/NextVPN/releases/download/v1.1.0-linux/nextvpn_1.1.0-1_amd64.deb) | `sudo apt install ./nextvpn_1.1.0-1_amd64.deb` |

Ниже — как собрать то же самое из исходников.

### Fedora

```sh
sudo dnf install rpm-build meson gettext desktop-file-utils appstream gtk4-devel glib2-devel
linux/packaging/fedora/build-rpm.sh
sudo dnf install ~/rpmbuild/RPMS/x86_64/nextvpn-*.rpm
```

### CachyOS, Arch, EndeavourOS, Manjaro

```sh
cd linux/packaging/arch
makepkg -si
```

### NixOS

Запустить без установки:

```sh
nix run github:Just-ElC/NextVPN
```

Или добавить в конфигурацию (flake):

```nix
{
  inputs.nextvpn.url = "github:Just-ElC/NextVPN";

  outputs = { nixpkgs, nextvpn, ... }: {
    nixosConfigurations.my-pc = nixpkgs.lib.nixosSystem {
      modules = [
        nextvpn.nixosModules.default
        { programs.nextvpn.enable = true; }
      ];
    };
  };
}
```

Для режима VPN нужен NetworkManager (`networking.networkmanager.enable = true`,
на десктопах он обычно уже включён); без него модуль предупредит при сборке, а
приложение будет работать через системный прокси. Ничего больше настраивать не
нужно: ни правил polkit, ни `checkReversePath` — маршрутизация NextVPN проходит
строгую проверку обратного пути файрвола NixOS как есть. Модуль заодно включает
`programs.dconf`, без которого системный прокси GNOME/GTK не доходит до других
программ.

`nix run` запускает программу без установки: в трее значок есть, но в меню
приложений её нет. Чтобы она появилась в меню (и в лаунчере caelestia) со своим
значком, поставьте её модулем выше или `nix profile install github:Just-ElC/NextVPN`.

Пакет также доступен как `nextvpn.packages.<system>.nextvpn` и через
`nextvpn.overlays.default`. На aarch64 движок собирается из исходников той же
ревизии.

### Ubuntu, Debian

```sh
sudo apt install meson gettext dpkg-dev
linux/packaging/debian/build-deb.sh
sudo apt install ./nextvpn_1.1.0-1_amd64.deb
```

### Любой другой дистрибутив (openSUSE и т.д.)

```sh
linux/install.sh --deps     # поставить недостающие пакеты (спросит sudo)
linux/install.sh            # установить для себя в ~/.local, без прав администратора
```

`linux/install.sh --system` ставит для всех в `/usr/local`,
`linux/install.sh --uninstall` удаляет (настройки сохраняются).

Без установки, прямо из репозитория: `linux/run.sh`.

**Что нужно:** Python 3.10+, PyGObject и pycairo, GTK 4.10+, libadwaita 1.4+,
iproute2; для режима VPN — NetworkManager; для сборки — meson и gettext.

## Как пользоваться

1. Нажмите большую круглую кнопку.
2. Дождитесь надписи **«Подключено»** — рабочий стол уже ходит через туннель.
3. Другая страна — вкладка **«Локации»**.
4. Нажмите кнопку ещё раз, чтобы отключиться.

Окно можно закрыть — приложение останется в области уведомлений (трее).

### Режим VPN: через туннель идёт всё

По умолчанию NextVPN работает как настоящий VPN. Через туннель идут все
программы: браузеры, Telegram, Discord, игры, Steam, терминал, `git`, `curl`,
вместе с DNS и IPv6, в любом окружении, тайловые оконные менеджеры тоже.
Это режим «пакетного туннеля» самого движка Psiphon — тот же, что у официального
приложения для iOS; серверы те же.

Как это устроено:

- **NetworkManager** создаёт интерфейс `nextvpn0`, принадлежащий вам. Поэтому
  ни root, ни пароль не нужны: так NetworkManager разрешает пользователю
  активного сеанса настраивать собственные подключения.
- Весь трафик направляется в `nextvpn0` правилами маршрутизации (таблица 28278).
  Локальная сеть — роутер, принтер, NAS, Docker — остаётся доступна напрямую.
- DNS тоже идёт в туннель: системный резолвер спрашивает `198.18.0.2`, а отвечает
  резолвер сервера Psiphon. Подмена DNS провайдером на это не влияет.
- Собственные соединения движка привязаны к вашему настоящему интерфейсу, так что
  туннель не заворачивает сам в себя. Работает и со строгой проверкой обратного
  пути (`rp_filter`, файрвол NixOS по умолчанию, `firewalld`).
- Сменилась сеть, например Wi-Fi на кабель, — NextVPN сам переподключится через
  новую.
- После отключения интерфейс, маршруты и DNS убираются. То же происходит, если
  приложение упало или его убили (`kill -9`): движок работает под отдельным
  процессом-сторожем, а при следующем запуске оставшееся убирается ещё раз.

Пока туннель подключается или переподключается, трафик никуда не уходит в
обход — он просто ждёт.

Если NetworkManager нет (например, только `systemd-networkd` или `iwd`), NextVPN
работает через системный прокси и пишет об этом на главной («Режим»).

### Режим системного прокси

**Настройки → Система → «Что идёт через туннель» → «Программы, которые
используют системный прокси»**. На время подключения NextVPN включает
системный прокси и возвращает ваши прежние настройки после отключения (и после
аварийного завершения — при следующем запуске):

| Где | Что меняется | Кто это читает |
|---|---|---|
| GNOME, Cinnamon, Budgie, любые GTK/GIO-программы | GSettings `org.gnome.system.proxy` | Firefox («использовать системные настройки прокси», так по умолчанию), Chrome/Chromium/Brave/Edge, программы GNOME |
| KDE Plasma | `~/.config/kioslaverc`, `[Proxy Settings]` | программы KDE, Chromium-браузеры в Plasma |

На Hyprland, Sway и других оконных менеджерах эти настройки читают лишь
немногие программы, поэтому там нужен режим VPN.

Пока туннель переподключается (смена страны, обрыв связи), прокси **не
снимается**, чтобы трафик не ушёл мимо туннеля.

Терминал и консольные программы читают только переменные окружения. На главной
странице у «Локального прокси» есть кнопка копирования — она даёт готовую
команду `export http_proxy=… https_proxy=… all_proxy=…` для терминала.
Локальные порты можно зафиксировать в настройках, чтобы прописать их в других
программах вручную. Локальный прокси работает и в режиме VPN.

### Страны

Список стран — это то, что сеть Psiphon сейчас предлагает через эти серверы
(сейчас 17: Австралия, Австрия, Великобритания, Германия, Индия, Ирландия,
Испания, Италия, Канада, Литва, Нидерланды, Польша, Сингапур, США, Франция,
Швеция, Япония), тот же, что у Windows-версии. Он приходит от
движка и сам расширяется, когда в сети появляются новые серверы. В некоторых
странах серверов мало, и в сильно фильтруемой сети через них бывает трудно
подключиться: если подключение затянулось, NextVPN подскажет выбрать «Самая
быстрая» — там серверов во много раз больше.

### Трей

Значок в трее работает по протоколу StatusNotifierItem: KDE Plasma, XFCE,
Cinnamon, Budgie, LXQt, waybar, caelestia и другие оболочки на quickshell — сразу,
в том числе при запуске через `nix run` или из исходников. В **GNOME** нужно
расширение AppIndicator (в Fedora — `gnome-shell-extension-appindicator`, в
Ubuntu уже включено). Без трея закрытие окна завершает программу.

Левый щелчок по значку — показать/скрыть окно, средний — подключить/отключить,
правый — меню.

### Командная строка

```
nextvpn                 открыть окно (или показать уже запущенное)
nextvpn --minimised     запустить в трее
nextvpn --connect       подключить
nextvpn --disconnect    отключить
nextvpn --toggle        подключить или отключить
nextvpn --quit          отключить и закрыть запущенную копию
```

Работает всегда одна копия: повторный запуск передаёт команду уже запущенной.
Удобно для горячих клавиш рабочего стола.

## Где что лежит

| | |
|---|---|
| `~/.config/nextvpn/settings.json` | настройки |
| `~/.local/share/nextvpn/` | данные движка, сгенерированный конфиг, резервная копия настроек прокси |
| `~/.config/autostart/io.github.just_elc.NextVPN.desktop` | автозапуск (если включён) |

В режиме VPN на время подключения есть ещё подключение NetworkManager `NextVPN`
(только в памяти, на диск не сохраняется) с интерфейсом `nextvpn0`.

Программа ничего не пишет вне этих мест и никогда не скачивает замену самой себе.

## Если что-то не работает

- **Журнал** (последняя вкладка) показывает всё, что делает движок; кнопка
  «Копировать всё» — для вопроса в issues.
- Подключение висит долго — выберите «Самая быстрая» или включите «Увеличить таймауты подключения»
  в настройках.
- Режим VPN не включается из-за прав — NetworkManager разрешает это без пароля
  только пользователю, вошедшему в рабочий стол. Из SSH или cron это не работает;
  там можно переключиться на системный прокси.
- Посмотреть, что настроено во время подключения: `nmcli connection show NextVPN`,
  `ip rule`, `ip route show table 28278`, `resolvectl dns`.
- Если вдруг после сбоя пропал интернет, а NextVPN не запущен:
  `nmcli connection delete NextVPN` (то же делает сама программа при запуске).

## Разработка

```sh
linux/run.sh                                  # запустить из исходников
cd linux && python3 -m unittest discover -s tests -t .   # тесты
meson setup _build && meson test -C _build    # то же через meson, с проверкой .desktop и metainfo
```

Тесты движка используют фейковый движок с тем же протоколом, а тесты режима VPN —
ещё и фейковые `nmcli` и `ip`, так что система не меняется. С настоящим движком:
`NEXTVPN_REAL_ENGINE_TEST=1`. Настоящее подключение к сети Psiphon с запросом
через туннель: `python3 linux/tools/connect-check.py`, в режиме VPN —
`python3 linux/tools/connect-check.py --vpn` (проверяет, что обычный запрос и DNS
уходят через сервер Psiphon и что после отключения ничего не осталось). CI
(`.github/workflows/linux.yml`) делает всё это на каждом PR, собирает пакеты для
всех дистрибутивов, а по тегу `v*-linux` или при ручном запуске с параметром
`release_tag` публикует их релизом (во втором случае workflow сам создаёт тег). Тесты трея и view-model проверяют D-Bus и нужно
запускать под `dbus-run-session`.

| Каталог | |
|---|---|
| `nextvpn/core/` | всё, кроме интерфейса: движок, конфиг, режим VPN, системный прокси, автозапуск — без GTK |
| `nextvpn/ui/` | интерфейс на GTK 4 / libadwaita, трей, уведомления |
| `engine/` | Linux-сборка движка, воспроизводимая из исходников (общие `base.config` и `server_list.dat` — в `/engine`) |
| `po/` | переводы |
| `packaging/` | Fedora, Arch, Debian, Nix, архив исходников, заметки к релизу |
| `tools/` | сборка движка из исходников, проверка подключения к сети Psiphon |

Переменные окружения: `NEXTVPN_ENGINE` — путь к другому движку,
`NEXTVPN_ENGINE_DIR` — каталог с другими `base.config` и `server_list.dat`.
